## Populations and calculations

- **Source record, not unique asset:** CI identity is `(source_system, source_id)` ([model](../app/models/ci.py), `uq_ci_source_system_source_id`). Intune and SolarWinds may mirror the same physical device. No verified cross-source deduplication count exists. `C.total_cis` and the overview fleet counts describe active source records, not unique enterprise assets.
- **Active:** inventory SELECTs exclude retired CIs through [database](../app/core/database.py), `active_inventory_scope`. This is record lifecycle, not operational Up status. A list with no matches can be zero while a source summary with no ingested data returns 503. Never erase this difference.
- **Classification counts:** `C.total_endpoints` is the Intune population; SolarWinds records partition into servers, network and unclassified. `S.metrics.total_server_nodes` is a legacy alias of all nodes, not classified servers. CMDB provenance verifies Intune + all three SolarWinds categories = total before rendering percentages.
- **Endpoint compliance:** `I.decision_metrics.confirmed_compliance` = 100 × compliant / all active Intune records. Unknowns remain in the denominator. Known grace, error, conflict and other recognized states are not compliant. `known_count` is field coverage, not compliant count. `metrics.other_compliance` combines all states other than compliant/noncompliant; it is not synonymous with unknown. Preserve raw `compliance_breakdown` labels separately from normalized `compliance_state_counts`.
- **Operational status:** persisted source classification. SolarWinds normalizes codes to Unknown, Up, Down, Warning, Shutdown, Unmanaged or Critical; Intune status represents compliance. An Unmanaged node is not Down. Do not combine these sources into one operational-status rate.
- **Health tier:** local derivation, not an upstream alert or SLA. Intune: Compliant → High, NonCompliant → Low, others → Medium. SolarWinds uses status plus resources: base Down/Critical → Low; CPU or memory >90 → Low; CPU ≥75 or memory ≥80 → Medium unless base is Low; otherwise retain base. Unknown/Unmanaged can therefore be Medium. [Normalization](../app/services/telemetry_sources.py), `ORION_HEALTH_MAP`, `classify_solarwinds_health`.
- **Nodes reporting Up:** `S.decision_metrics.current_node_status` = 100 × Up / (all active nodes − explicitly Unmanaged). Unknown remains in denominator. `all_fleet_up` includes Unmanaged too. Legacy `metrics.monitored_availability_pct` excludes both Unmanaged and Unknown and is **not interchangeable** with the decision metric.
- **Resource pressure:** `resource_pressure.numerator` counts any valid CPU ≥75 or memory ≥80; denominator is all active SolarWinds nodes. Values must be finite percentages in [0,100]. `known_count` requires both readings, so observed breaches can overlap incomplete telemetry; never add the two counts as disjoint categories. With neither reading anywhere, `value` is null. Resource health counts partition normal/elevated/critical/insufficient_data, distinct from stored health tiers.
- **Top saturated servers:** same warning thresholds, but only classified servers, ordered by maximum available CPU/RAM and limited to ten. `total_saturated_nodes` counts this server-only candidate set despite its name. This is not the denominator or complete list for the all-node resource-pressure KPI.
- **Storage:** median of valid per-device `100 × (total_storage_bytes − free_storage_bytes) / total_storage_bytes`; fleet capacity = 100 × summed used bytes / summed total bytes. `avg_storage_used_pct` aliases the weighted capacity measure, not an arithmetic mean. Sample size and sample / active Intune record count qualify both measures. Missing/invalid measurements are excluded; numeric null must not be coerced to measured zero.
- **Distributions:** count source records by supplied field; percentages divide by that distribution's scoped record population. OS diversity is number of returned OS keys, possibly including Unknown; it is not OS currency/security. Raw group-count dictionaries can contain categories outside a chart's hardcoded labels; reconcile before displaying.
- **Forecast:** linear regression of the latest successful Intune `records_processed` per UTC day, default 14-day lookback, at least seven observed days, seven-day horizon. Count is extraction/processing history, not necessarily unique assets or a retirement-adjusted forecast. No ML, confidence interval or operational-outage prediction is supplied. Do not equate it with the current inventory summary.

## Locations and comparability

Canonical `location_id`/`level` and raw `location` are different. Intune uses local name-prefix mapping; SolarWinds uses source aliases/custom properties. Approved local mappings are assignment evidence, not a native Intune site field. W groups raw source-location spellings; L uses canonical reporting groups. Avoid calling either a verified count of physical offices or countries.

W `availability_pct` is snapshot Up / all nodes at that raw location; `health_status` applies 90/75 bands to that snapshot ratio. It is neither H's monitored denominator nor uptime. `region` is not a verified regional catalogue (assigned locations currently have no region). Slug `id` is derived from source spelling, not canonical L identity. Do not use W region/latency/averages to activate the standalone regional or SLA shells.

For a canonical group define C = compliant Intune / endpoints ×100; R = valid check-in within seven days / endpoints ×100; H = Up SolarWinds / nodes excluding explicit Unmanaged ×100.

| Score | Existing calculation | Required evidence |
| --- | --- | --- |
| Endpoints | `(40C + 25R) / 65` | C and R |
| Infrastructure | `H` | H |
| Combined | `(40C + 35H + 25R) / 100` | C, H and R |

Each component exposes numerator, denominator, `known_records`, `coverage_pct`, value, `usable`, reason and source. A component needs a positive population and ≥95% known-field coverage for a value; it is usable only when its source is FRESH. Any required unusable component, unresolved/conflicting mapping, or Unassigned group makes the composite unavailable. No favorable component substitutes for missing data.

Status uses exact values before rounding: critical below 75 (composite or any required component); warning below 90, or Down/Critical nodes for infrastructure-bearing scores, or latest required-source FAILED/PARTIAL; otherwise healthy. Display rounds score to one decimal. These are application policy bands, not SLA targets or business impact.

Compare only the same score mode, source scope, reporting level, policy and compatible mapping/observation context; always expose denominator and coverage. Auto mode mixes calculations. Current All levels/Auto browsing warns but does not enforce comparability. Unassigned is separate coverage, not a scored competitor. Group issues are overlapping investigation predicates, not additive affected-device totals.

`issues`: noncompliant; other_compliance; check-in >7 days; check-in >30 days (subset of >7); missing/invalid/far-future check-in; Up/Down/Critical/Warning/Unmanaged nodes; conflict/review mappings. Detail also supports `all`. Location name search is name-only, unlike global CI search. History is captured score observations, not continuous uptime; the UI filters to the current policy and mapping revision.

## Time and evidence states

| Term / state | Meaning and required UI behavior |
| --- | --- |
| Last successful source sync | F per-source maximum successful completion; legacy successful ALL runs can contribute to both sources. Window normally `max(900, 2.5 × SYNC_INTERVAL_SECONDS)`. Overall uses worst source, UNKNOWN before STALE before FRESH. Query failure can also yield UNKNOWN: avoid claiming it proves no run ever occurred. |
| Latest attempt | Y source status/completion, independent of last success. FAILED/PARTIAL can coexist with a recent successful snapshot. Y `last_sync`/age follows the newest completed latest-source run, including failure; it is not F's last success or oldest source age. RUNNING is not a failure. |
| Record mirror time | CI `last_sync_time` is ingestion observation, not upstream measurement time. Summary `last_sync_time` and decision `observed_at` are maxima, not proof every row was observed together. |
| Device check-in | Intune `attributes.last_sync_date_time`; independent of mirror freshness and compliance evaluation time. Buckets: ≤7 days, >7–30, >30, missing/invalid. >5 minutes in the future is invalid. |
| Generated / checked / as-of | Summary `generated_at` is computation time; client freshness check time is local; L `as_of` is assessment time. None alone refreshes the underlying telemetry. Summary cache TTL is 300 seconds with last-good fallback on loader failure; separate F/Y calls may describe newer metadata than displayed counts. |
| Loading | Evidence pending; use text/status and busy state, never a provisional healthy value. |
| Zero | A successful available scoped result can be 0. Zero denominator means no population, not 0% health. Preserve 0% when numerator is zero and denominator positive. |
| Unknown / unavailable / failed | Unknown field, absent source success, API/DB failure and unsupported metric are distinct reasons. Null/omitted/503 must not become zero or healthy. Keep unaffected sources visible. |
| Stale / partial | Stale describes last-success age; partial describes incomplete ingestion or incomplete page evidence, not an interchangeable freshness status. Retain last-good values only with their original provenance/time and a warning. Do not infer FRESH from HTTP 200. |

Client formatting must preserve these semantics without changing backend contracts. Aggregate percentages, percent storage, record counts, elapsed durations and wall-clock timestamps need distinct units. No unique-asset total, uptime SLA, business-impact score, incident frequency, forecast confidence interval, recovery-key coverage or policy-failure details is supported by the fields above.
